# MEEKA 上线与数据存储检查

检查日期：2026-10-26（北京时间）。结论：资讯栏目可以继续试运行，会员站尚不具备全面开放条件。

## 自动更新：实际运行状况

检查时，资讯库共有 76 条采集资料、51 条可公开内容。公开内容按最后写入/更新日统计：10 月 23 日 15 条、24 日 17 条、25 日 19 条。worker 心跳正常，9 个启用信源最近的抓取均正常，当前自适应抓取间隔约 60 分钟。

因此不是采集完全停止。主要问题是：

1. 页面原来不会在保持打开时定时刷新，读者需要重新访问。
2. 列表按来源时间排序，延迟处理的旧资料不会必然排到最前。详情页显示固定一篇文章，也不会变成资讯流。
3. 模型预算在每滚动 24 小时达到 100 次请求后停止新增模型处理，检查时有 21 条资料因此等待。100 次请求不是 100 篇文章，也不是金额上限；当前回执成本字段为空，不能视作免费。
4. 日报与事件摘要也使用同一模型额度。观察到日报历史失败和事件摘要因小时额度耗尽失败的记录；25 日日报后来已产生“暂无新入选内容”的一期，不能把该文案解释成整个行业没有变化。

本次补上每 5 分钟检查更新、切回页面时检查到期更新、手动刷新入口，保留分类、搜索和页码；搜索输入或选中文字时跳过自动刷新。明确区分“来源发布于”和“本站内容更新于”。页面刷新只读取公开接口，不调用模型。

没有提高模型预算、降低内容门槛、伪造新文章或重置已有调用记录。

## 数据究竟存在哪里

| 数据 | 当前去向 | 可靠性边界 |
|---|---|---|
| 采集文章、编辑稿、公开状态、模型回执和任务记录 | 新 Supabase PostgreSQL，检查时数据库约 30 MB | 已确认持久化；容量暂不是瓶颈，仍需要备份恢复能力 |
| 现有主站会员身份、资料与社区数据 | 旧 Supabase 项目，当前暂停 | 未恢复前不能确认可读写和完整性；不可直接改环境变量指向资讯库代替迁移 |
| 静态手册、Logo 等 | GitHub 源码＋Vercel 公共静态文件 | 可随部署恢复，但公开 URL 不适合承担付费私有文件授权 |
| 用户私有文件、反馈截图、上传原件 | 尚未配置云端私有对象存储 | 云端上传保护应保持失败关闭；不能依赖容器 `/tmp` 持久保存 |
| 部分搬品工具的临时资料 | 浏览器 localStorage，代码最多保留 30 条 | 清理浏览器、换设备后可能丢失，不是账户云端存储 |
| 异地备份 | 应用级尚未配置 | 没有完成一次恢复，就不能确认数据可恢复 |

新库公共表对 anon/authenticated/PUBLIC 没有直接授权。安全建议中的 47 项“RLS 已启用但无 policy”为 INFO，与资讯数据仅由服务端读取的设计一致，不应为了消除提示而开放匿名权限。另有 6 个 pg-boss 函数 search_path 警告、1 个扩展位于 public 的警告，需结合队列升级及私有 schema 权限处理。

参考：[Supabase RLS 无策略提示](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)、[函数 search_path 提示](https://supabase.com/docs/guides/database/database-linter?lint=0011_function_search_path_mutable)、[扩展 schema 提示](https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public)。

## 托管与商业化安排

Vercel 截图此前显示为 Hobby，本次连接无法读取团队计费与完整运行日志，因此不能确认当前套餐或额度余额。正式商业服务前需核对套餐：[Vercel 官方说明 Hobby 限个人非商业用途](https://vercel.com/docs/plans/hobby)。未自行升级或扣费。

Supabase 的[备份说明](https://supabase.com/docs/guides/platform/backups)建议免费项目定期导出并保存异地备份；可访问的自动每日备份与付费套餐相关。平台级备份配置和恢复点尚未从账户中完成核实，不能把“数据库健康”当作“备份已完成”。

建议先明确每日模型金额预算与每月基础设施预算，再确认生产托管和备份方案。无需重新提供已经保存的数据库密码或 API key。

## 核验范围与限制

本轮包含公开页面、浏览器交互、源码、两个 Supabase 项目状态、新库只读统计、安全/性能建议、生产依赖扫描及前端回归。没有进行压测、攻击性渗透、真实付款、发送注册验证邮件、跨账号业务写入或数据库恢复测试。

直接探测后台 `*.vercel.app` 域名在本机与浏览器请求环境中超时；Vercel 的运行日志与保护链接工具返回 403。主站服务端读取的真实资讯正常，数据库和 worker 心跳正常；这两点不能替代当前后台匿名管理接口的端到端验证。主站搬品 API 的未登录请求已确认 401。

这些访问限制不应解释为网站本身全部宕机，也不能当作鉴权已通过。应补一个部署侧的健康与权限探测，确认只有公开资料接口匿名可读，管理接口始终需要认证。

后台依赖与成员系统未变更，因此本轮没有重新运行框架的 946 项数据库测试；此前结果不能作为本轮后台升级验证使用。
